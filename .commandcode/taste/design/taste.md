# Design taste

- Wants the entire site to feel like one cohesive design system — every page (homepage, Work, Project Detail, Contact, testimonials) must share the same typography, spacing, borders, accent color, mono labels, and container rhythm. Confidence: 0.9
- Treats the existing homepage and its components as the visual source of truth: when building or changing a new page/section, reuse and adapt existing homepage components and design language instead of creating a parallel look. Confidence: 0.9
- Explicitly rejects "generic SaaS / AI-generated template" aesthetics: no repeated icon+title+description cards, no pills everywhere, no excessive rounded containers, heavy shadows, gradients sprayed around, glassmorphism, or fake dashboard/diagram graphics — and no tool logos or icon badges in marketing/proof content (icons only when necessary), no stock imagery, and no AI-generated graphics. Confidence: 0.9
- Prefers a restrained "premium editorial / technical" character where typography, thin dividers, whitespace, and careful alignment carry the design rather than decoration. Confidence: 0.85
- When the same content type appears in multiple places, wants the exact same approved component used everywhere (e.g., homepage `upworkproof` reused for project testimonials) — identical layout, only the data changes. Confidence: 0.85
- Motion should be subtle and nearly invisible in effect: small fades/translations (roughly 8–20px), opacity + transform only, short staggers, elements settle once they enter (no constant scroll-linked movement), and prefers-reduced-motion respected. Confidence: 0.85
- When a change moves existing components to new positions (e.g., swapping two blocks between hero columns), each moved element keeps its own original motion delay/timing — repositioning must not re-stagger, re-time, or otherwise alter the animation behavior of the moved blocks. Confidence: 0.55
- Do not use animation to compensate for layout problems, and do not fill intentional whitespace with extra cards or decorative elements — whitespace is part of the design. Confidence: 0.8
- Mobile should be deliberately designed (compact, less animation, no wasted left whitespace, no horizontal overflow, wider reading area) rather than a simple stacking of the desktop layout. Confidence: 0.8
- For row-based layouts (e.g., the contact methods list), alignment must come from one shared fixed CSS grid definition — no per-row margins, negative margins, or individual positioning hacks. Confidence: 0.8
- Decorative/background shapes must stay behind content and never cross text, icons, or borders or reduce readability; a background line that intersects headline/body copy reads as a rendering bug and should be removed entirely — if any decoration is kept, it must sit fully behind text at very low opacity (under ~8%) and be positioned so it never intersects headline or body text. Confidence: 0.85
- Admin/UI controls must be accessible: toolbar and button controls need accessible labels, meaningful active states (e.g., aria-pressed), keyboard operability with visible focus, and `type="button"` when inside a form so they never submit it. Confidence: 0.8
- When an optional value is missing, never render an empty joiner/separator — e.g., show only the client name when company is empty, not "Name · ". Confidence: 0.6
- Truncates long text previews visually: prefers CSS line-clamping (e.g., `line-clamp-3`) so the browser decides the cutoff per width/font/breakpoint, and explicitly rejects JavaScript string slicing (`substring`, `slice`, split, character/word counts) because character counts ignore responsive width, font size, and mobile vs desktop. Confidence: 0.9
- Wants card previews compact and scannable: roughly 2–3 lines with a visual ellipsis, full text when the content is short, never a long block that inflates a card's height. Confidence: 0.8
- When content looks unnecessarily narrow inside a card, remove the specific layout constraint causing it (stray max-width/fixed width/narrow column/excess padding) so the text fills the available content width and aligns with the card's content edges — fix the actual constraint rather than compensating with font-size or global padding tweaks. Confidence: 0.7
- For image accessibility, wants the standard semantics applied deliberately: meaningful alt text for content images, empty alt (`alt=""`) for decorative images, and no alt text that repeats what the surrounding element already provides via an accessible name (e.g., a homepage logo link carrying an aria-label). Confidence: 0.6
- For header/navbar refinement, wants restrained, near-invisible micro-interactions: subtle color/opacity transitions and a thin (1px) underline that scales in on hover; an understated active state; and nav links that always read as secondary to the primary CTA — no flashy hover effects or loud active markers. Confidence: 0.7
- Wants the brand logo displayed at a clearly legible, prominent size in the header so it reads as a real brand mark rather than a tiny icon — sized by width with automatic height so the natural aspect ratio is never stretched or distorted. Confidence: 0.7
- Header contents (logo, nav text, CTA) must share one optical center line with precise vertical centering — nothing may sit visibly high or low relative to the others. Confidence: 0.6
- Keeps header/content within the existing container/max-width system with breathing room from the viewport edges rather than making content span the full viewport for balance. Confidence: 0.6
- When the user supplies an external design reference, treat it strictly as inspiration for structure, spacing, and interaction patterns only — never copy its colors, typography, branding, or visual style; the site's own existing theme is always the source of truth. Confidence: 0.8
- Prefers the mobile navigation/menu to be a full-height overlay drawer (fixed to the viewport, `100dvh`, spanning top to bottom) rather than a small dropdown panel under the header; while open, the page behind must not scroll or remain interactable (body overflow lock + smooth-scroll `prevent`); the drawer layout should be: logo + close button in its own top bar under a subtle divider, vertical links with generous spacing, and the CTA anchored at the bottom — spacious, never cramped. Confidence: 0.75
- Reuses the project's existing responsive breakpoint system; do not arbitrarily introduce a new breakpoint when the design system already has one. Confidence: 0.8
- Overlay/drawer menus must be keyboard accessible: Escape closes, focus moves to the close button on open and returns to the trigger on close, trigger carries `aria-expanded`/`aria-controls`, touch targets are adequate (~44px), and activating a nav item closes the menu before navigating. Confidence: 0.7
- Display/headline type must use the site's sans/grotesk family (matching body text and buttons), never the mono font; monospace is reserved for small technical labels — eyebrows, step numbers, stat labels — because mono at large display sizes reads as mismatched, heavier than intended, and causes awkward line breaks. Confidence: 0.85
- The hero H1 copy must be used word-for-word as specified with the original composition/natural wrapping; the approved treatment is an otherwise restrained headline in the site's navy heading color where a single green accent phrase is highlighted by a subtle pale-green organic underline beneath the highlighted words — no box, no pill, no gradient, no special coloring of other words, and no size increase to compensate for shorter copy. Confidence: 0.9
- Headlines should break naturally: prefers `text-balance`/natural wrapping over hard-coded `<br>` line breaks that trap short phrases ("around your", "business.") on their own line. Confidence: 0.7
- The hero is an open editorial two-column composition: left-column content (eyebrow, H1, paragraph, CTAs, process strip) sits directly on the hero background — never inside a bordered card, white shell, fill, frame, or added visual container. Only the right column's approved proof-of-work card is a card; the two columns are not wrapped into identical card shells. Confidence: 0.9
- Eyebrow/micro-label treatment: a small colored dot (or short accent line) instead of a plain dash, uppercase text with increased letter-spacing, and the accent green deepened/darkened when used as foreground on a light background for contrast. The prefix glyph must carry a deliberate visual relationship to the label — a short horizontal accent line (4–6px) or a filled dot aligned on the text baseline; never a lone floating dot with no anchoring to the text. Confidence: 0.75
- Site palette: navy-on-light (#132030-ish) with a green accent (#2FAE72-ish), light background, no heavy shadows or gradients beyond subtle background texture. Card/block surfaces must be white or off-white only — flat gray/lavender background fills look unfinished and are explicitly rejected ("no gray fills"). Confidence: 0.8
- The hero process strip keeps the original thin-column editorial treatment: small green mono step numbers (01–04) above muted gray labels in narrow columns separated by hairline dividers inside the border-y strip — no circles, chips, timeline nodes, connector lines, or green dots. Confidence: 0.85
- No dashboard-style statistics in the hero: reject separate stat cards, large metric blocks, giant numbers, colorful icons, pills, and shadows. The approved credibility treatment is a compact editorial proof row directly under the CTAs (e.g., `20+ CLIENTS` and `5.0 UPWORK RATING`): small mono uppercase labels with slightly stronger numerals in muted navy/gray and subtle green accents, segments separated by thin hairline vertical dividers — every displayed figure must be backed by verified existing site content/data or it is omitted. Confidence: 0.85
- The approved hero composition is an intentionally asymmetric two-column editorial layout: the right proof stack (Real Client Work + UpworkProof) starts slightly higher than the left body and is allowed to extend lower than the left process strip — never vertically center the columns or force equal end heights. Keep the column gap moderate so both sides read as one composed system (excessive empty horizontal space between columns is a defect), keep shared clean edges (all left items on one consistent left edge; right stack sharing exact left/right edges), and do not make the hero unnecessarily tall — the process strip should stay within or near the first viewport. Confidence: 0.75
- The hero's two columns should carry complementary, non-duplicated proof: the left side communicates scale and specialization (e.g., restrained GHL stats like subaccounts/agencies/A2P), the right side communicates real-client evidence and testimonials (Real Client Work + UpworkProof) — never repeat the same claim on both sides (e.g., don't show the Upwork rating or a client count under the CTAs when UpworkProof already sits on the right). Confidence: 0.65
- When choosing between adding something and preserving the original design, preserve the original: do not add cards, stat panels, badges, decorative graphics, or tool logos to fill whitespace or balance columns — whitespace is intentional and part of the premium/editorial character, and a change should make the page look like the same site with a small refinement, never like a redesigned section. Confidence: 0.85
- Intra-section layout should follow one consistent, generous vertical rhythm between stacked elements (eyebrow → headline → paragraph → CTAs → steps → stats), with roughly 40–48px between major stacked sections so the column breathes at the same rate as the neighboring card's padding — not tight stacking. Confidence: 0.7
- For numbered methodology/step lists, keeps a stepped typographic hierarchy: the step number is the smallest technical element (green mono, ~10–11px), the concept is a short navy uppercase semibold heading (~12–13px), and the description is muted navy normal-case text (~12–13px, line-height ~1.3) — numbers/concepts must not be oversized and descriptions must not be tiny; sizes stay moderate and even throughout. Confidence: 0.6
- In the hero, the H1 is the dominant message and no supporting block (methodology, proof, stats) may visually compete with it; the composition follows an explicit narrative hierarchy (positioning → method → proof) so supporting sections read as a direct answer to the headline, never as parallel standalone UI panels. Confidence: 0.7
- For proof/metric labels that span two lines, prefers intentional controlled line breaks (with forced markup, e.g., `<br/>`) so all metrics share a consistent vertical rhythm and never wrap unpredictably per width. Note: this applies to small technical/credential labels under a number, not to headlines — headlines should still break naturally (`text-balance`). Confidence: 0.7
- Metrics that represent professional experience/credentials should read as an "experience signature", not a statistics widget or SaaS dashboard: numbers semibold (600–700) and prominent but subordinate to the H1, navy numerals with a small green accent; everything stays directly on the background (no cards/pills/boxes/shadows/glassmorphism/outer borders), separated only by short 1px hairlines between columns; no icons, badges, checkmarks, headings, or count-up animations. Confidence: 0.8
